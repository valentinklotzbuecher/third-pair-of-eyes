# Synthetic data for code review

Patient data usually cannot be sent to the model provider. Synthetic data lets the
code run anyway, which checks what the code does (it runs, its filters and derived
variables implement the printed definitions, its models are the specified ones, its
estimators recover a known effect) but never what the real data say. Nothing produced
here supports or contradicts a printed number.

## Rules

1. **No real data is read, ever.** The schema-only route uses the code and the
   documents. The codebook route uses a codebook the statistician made locally with
   `assets/make_codebook.R` and checked before handing over. The provided route uses
   dummy data the statistician made. If a file of unknown origin turns up, stop and
   ask (`stats-review` rule 11).
2. **Everything is generated by a seeded script** in `work/synthetic/`, re-run clean,
   with a log. No hand-edited data files.
3. **The contract comes first.** Data are generated from `contract.csv`, and the
   generated data are checked back against it.
4. **Expectations before runs.** Every edge case and every planted effect has its
   expected consequence written down before the product's code runs on it.
5. **Synthetic data stays in the review's folders**: `work/synthetic/` and the working
   copy `work/pkg/`, never `01_product/` or `04_data/`.

## Routes

| Route | Input | Use when |
|---|---|---|
| schema only (default) | the product's code, the SAP or protocol definitions, the CRF or data dictionary if in `02_governing/` | always possible; levels and ranges are plausible guesses, recorded as such |
| codebook | `05_synthetic/codebook.csv` (and `structure.csv`) from `make_codebook.R` | the code depends on exact variable names, levels, codes or visit structure that the documents do not give |
| provided | dummy data in `05_synthetic/` (test records from the data-management system, the dummy data a SAP was programmed on) | the statistician already has it |

**Codebook route, for the statistician.** In R, on the machine where the data are
allowed to be:

```r
source("<stats-synthetic-data skill>/assets/make_codebook.R")
cb <- make_codebook(list(baseline = baseline_df, visits = visits_df),
                    id_vars = "patient_id", k = 5)
write_codebook(cb, "codebook")      # writes codebook/codebook.csv and codebook/structure.csv
```

The codebook holds variable names, labels, types, factor levels (levels with fewer
than `k` records are pooled and not named), numeric ranges rounded outward, missingness
rounded to 5 percentage points, date ranges at month resolution, rows per participant
for repeated measures, and no values from free-text or identifier columns. Read it
before handing it over, and delete anything you would not show a colleague outside
the study (an unusual variable name or level can itself be disclosive).

## Steps

1. **Data contract.** Find every dataset the code reads (`review/intake-scan.json`
   lists the read calls) and every variable it uses: `$` and `[[ ]]` access, `dplyr`
   verbs, model formulas, joins, `factor()` levels and comparisons (`== "A"`,
   `%in% c(...)`), date handling. `symbols_in_code()` in `assets/synthesize.R` lists
   the candidate names from the parsed code. Write
   `work/synthetic/structure.csv` (one row per dataset: `dataset | file | format |
   grain | n_rows | key | notes`) and `work/synthetic/contract.csv` (one row per
   variable: `dataset | variable | type | levels | unit | min | max | missing_codes |
   p_missing | role | source`), where `type` is one of `id, integer, double, factor,
   ordered, logical, character, date, datetime`, `role` one of `id, arm, stratum,
   centre, outcome, covariate, time, event, visit, other`, and `source` cites the
   code line, document page or codebook row each entry comes from. A guessed entry says
   `guess` in `source`.
2. **Generator.** Write `work/synthetic/generate.R`, which sources
   `assets/synthesize.R`, sets one seed, and writes three variants at the paths and in
   the formats the code reads:
   - `base`: `synth_dataset()` from the contract, at the planned sample size, with
     plausible marginal distributions;
   - `edge`: `base` plus documented edge cases from `edge_cases()` (a missing outcome,
     a missing covariate, boundary values, a value equal to a cut point, a duplicated
     identifier, an out-of-window or out-of-order date, a factor level absent from
     the data, a participant with a single visit), each with its expected effect on the
     analysis sets and derived variables in `work/synthetic/edge-expectations.csv`
     (`case | dataset | rows | planted | expected_effect`), written before any run;
   - `truth`: `R` replicate datasets with a known effect planted by `plant_effect()`
     on the estimand's own scale and analysis set (and known missingness by
     `plant_missing()` where the analysis claims to handle it), with the planted values
     in `work/synthetic/truth.json`.
3. **Check the data against the contract.** `check_contract()` re-derives types,
   levels, ranges and missingness from each generated dataset and compares them with
   `contract.csv`; the result goes to `work/synthetic/contract-check.csv`. A mismatch
   is fixed in the generator, never by editing the contract to fit.
4. **Hand over.** Copy the variant under test into `work/pkg/` at the path the code
   reads (the working copy only), run the product's code unmodified, and record in the
   review's manifest which variant each run used, with `data_mode = synthetic`.

## What the runs can and cannot show

| Run | Shows | Never shows |
|---|---|---|
| `base` | the code runs end to end; outputs have the expected structure | that a printed number is right |
| `edge` | analysis-set counts and derived variables follow the printed definitions; the code handles values the data contract allows | how often such cases occur in the real data |
| `truth` | the estimator targets and recovers the planted effect; interval coverage near nominal; the missing-data method behaves as stated | the size of the real effect |

## Output

`work/synthetic/`: `structure.csv`, `contract.csv`, `generate.R` with its log,
`contract-check.csv`, `edge-expectations.csv`, `truth.json`, and the generated
datasets under `base/`, `edge/`, `truth/`. When run inside a review, a short note in
the code-and-data report: which route, which variables were guessed, and the contract
check result.
